# AskLume 平台能力卡片升级设计

## 目标

按照用户提供的最新桌面参考图，升级首页“平台能力”区域中的四张卡片，使其与已经完成的核心优势、三大信息支柱形成统一的高端玻璃视觉语言，同时保留现有文案、下方诊断 CTA、页脚和整体响应式结构。

## 设计依据

- 唯一视觉依据：用户在 2026-08-12 提供的两张“平台能力”参考图。
- 当前首页已确认的风格：低调、克制、国际化、蓝紫玻璃材质、精细留白和轻量交互。
- 本次只改造四张平台能力卡片及其必要的区域间距，不扩展详情页或新业务功能。

## 桌面端布局

- “平台能力”眉题、标题和副标题保持原文不变并居中排列。
- 四张卡片保持单行四列、等宽、等高。
- 卡片高度约为 190–210px，圆角约 18–22px，间距约 18–22px。
- 卡片采用轻透白色玻璃底、细边框、柔和蓝紫内光和克制的下投影。
- 左上角放置 48–56px 的渐变图标底座，图标沿用现有四种语义图形。
- 标题位于图标右侧，正文位于标题下方，确保四张卡片阅读节奏一致。
- 左下角增加纯装饰箭头，用于表达能力延伸；它不是链接、按钮或键盘焦点。
- 右下角放大现有四种 CSS 3D 图形：平台球环、监测之眼、协作方块、定制球体。图形应占卡片约 30%–42% 的视觉面积，但不得遮挡正文。
- 卡片之间不再使用当前的小型尖括号流程连接，以匹配新参考图中独立能力模块的表达。

## 视觉材质

- 卡片背景使用多层半透明白色与蓝紫径向渐变，避免纯白平板感。
- 边框保持低对比度，仅在鼠标悬停时轻微增强。
- 图标底座具有柔和内发光，不使用强烈霓虹。
- 3D 图形继续使用 CSS 构建，增加高光、透明边缘、体积阴影和落地阴影，形成玻璃或晶体观感。
- 区域背景保持白色，并加入非常弱的左右蓝紫氛围光，与参考图两侧的方块色雾呼应；不新增抢眼的大型装饰。

## 鼠标与动效

- 复用现有 `PointerGlowCard`，让光晕位置随指针移动。
- 悬停时卡片最多上浮 4px，阴影和边框轻微增强。
- 3D 图形根据指针坐标产生最多约 5–7px 的反向视差，不进行连续旋转。
- 装饰箭头悬停时只允许轻微水平位移或颜色增强，不具备点击语义。
- `prefers-reduced-motion: reduce` 下关闭卡片位移、视差和箭头位移，内容立即呈现。

## 响应式布局

### 平板端

- 1023px 及以下切换为两列。
- 保持卡片足够宽，正文和 3D 图形互不遮挡。
- 卡片高度可略微降低，但仍保留新版玻璃构图。

### 手机端

- 768px 及以下切换为单列。
- 卡片高度约 150–170px，图标与正文保持左侧阅读区。
- 3D 图形缩小并固定于右下角，正文区域保留安全宽度。
- 卡片之间不使用可见的桌面流程尖括号；保留当前页面整体纵向节奏，无横向溢出。
- 360px 宽度下标题、正文和装饰仍不得重叠或裁切。

## 组件结构

- `CapabilitiesSection` 继续从 `homeContent.ts` 读取四项内容。
- 四张 `<article>` 继续使用唯一的 `aria-labelledby` 关联其 `<h3>`。
- 将普通 `<article>` 替换为复用的 `PointerGlowCard`，保留文章语义。
- 每张卡片包含：图标、文案、纯装饰箭头、CSS 3D 图形。
- 箭头和 3D 图形均设置为辅助技术不可见，不添加空链接或无效按钮。

## 测试与验收

### 组件测试

- 仍渲染四张由配置驱动的文章卡片。
- 每张文章保持唯一且正确的标题关联。
- 每张卡片具有对应 `data-art` 类型。
- 每张卡片包含一个辅助技术不可见的装饰箭头。
- 区域内不存在因箭头新增的链接或按钮。

### 视觉回归

- 1440px：一行四列，尺寸和构图接近参考图。
- 1024px：两列或符合当前断点定义的稳定布局，无横向溢出。
- 390px 与 360px：单列，图形不遮挡正文。
- 768/769/900/901 边界检查继续通过。
- 减少动态模式下悬停不产生位移。

### 完成标准

- 单元与组件测试全部通过。
- TypeScript 与正式构建通过。
- 全部 Playwright 视觉回归通过，并在人工确认视觉变化后更新基准。
