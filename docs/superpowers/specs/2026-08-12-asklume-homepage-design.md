# AskLume 高保真首页设计规格

日期：2026-08-12
状态：已完成口头设计确认，等待书面复核

## 1. 目标

根据用户确认的 AskLume 桌面端和手机端设计稿，实现一个高保真、可响应的官网首页。页面应具有克制、精密、国际化的 AI 科技品牌质感，同时忠实保留设计稿的内容、结构与毛玻璃方块 Banner 造型。

本次交付是纯前端首页，不接入预约、登录、搜索、语言切换或其他后端业务。页面保留必要的视觉交互：导航锚点、手机菜单、按钮状态、滚动入场和卡片反馈。

## 2. 唯一视觉依据

- 桌面稿：[`references/asklume-desktop.png`](references/asklume-desktop.png)，1024 × 1536。
- 手机稿：[`references/asklume-mobile.png`](references/asklume-mobile.png)，1195 × 1316；包含首页连续长页的分段截图和手机菜单展开状态。
- Banner 原素材：[`references/asklume-banner.png`](references/asklume-banner.png)，1195 × 896。

三份素材是实现时的唯一视觉依据。不得引用其他 AI SaaS 网站替换其视觉决策，也不得改变 Banner 方块的轮廓、层级、色彩节奏或排列方式。

## 3. 已选实现方案

采用混合高保真方案：

- 原 Banner 素材负责 Hero 的毛玻璃方块、综合色彩和底部光感。
- 标题、文案、按钮、导航、Dashboard、数据卡、内容卡片和页脚全部由 HTML/CSS/React 重建。
- Logo、功能图标和装饰图形重绘为清晰的 SVG 或 CSS 图形，不从低分辨率截图直接裁切。
- 动效使用 Motion 与 CSS transition；不引入 Three.js、Canvas 场景或视频背景。

技术栈：Vite、React、TypeScript、CSS Modules、Motion。测试使用 Vitest、Testing Library 和 Playwright 截图比对。

## 4. 页面结构

页面按以下顺序组织：

1. `Header`：品牌标识、桌面导航、搜索图标、语言按钮和主行动按钮。
2. `Hero`：左侧价值主张、说明、四个价值标签、两个按钮；右侧 `GlassDashboard`；底层使用原 Banner 素材。
3. `TrustStrip`：信任说明与七个低对比度品牌标识。
4. `BenefitsSection`：标题和三张核心优势卡片。
5. `PillarsSection`：被看见、被理解、被选择三大信息支柱。
6. `CapabilitiesSection`：AI 搜索与洞察、持续监测与预警、企业协同与资产管理、定制化智能方案。
7. `DiagnosticCTA`：宽幅渐变场景、诊断文案、两个按钮和光学球体。
8. 手机端专属的 `MobileDashboard`：位于 CTA 之后，重排 Hero 中的 Dashboard 内容。
9. `Footer`：品牌、导航和社交入口。
10. `MobileMenu`：独立的全屏菜单状态，包含导航、CTA、登录、语言、预约卡、联系方式与版权信息。

内容结构不增删。桌面与手机之间只改变排列、密度和显隐位置。

## 5. 响应式规则

### 桌面端

- 主要设计基准为 1024 px 视觉稿，并在 1440 px 宽屏验证。
- 内容使用居中的最大宽度容器；Hero 为左文右卡结构。
- Benefits 和 Pillars 使用三列布局，Capabilities 使用四列布局。
- Dashboard 位于 Hero 右侧，并与 Banner 的方块色带形成前后层次。

### 手机端

- 主要验证宽度为 390 px，并在 360 px 窄屏验证。
- 顶栏只保留 Logo 与菜单按钮。
- Hero 文案、标签和按钮纵向排列；Banner 使用同一原素材，通过裁切和定位呈现在下半部及右侧，不重新生成方块。
- Dashboard 从 Hero 中移除，移动到 CTA 后方。
- Benefits、Pillars 和 Capabilities 均改为单列卡片。
- Pillars 与 Capabilities 的连接关系使用轻量纵向引导线，不影响阅读。
- 手机菜单为完整覆盖层，结构和内容对应手机稿第四列。

断点以内容是否拥挤为准，预设在约 768 px 和 1024 px 附近；实现时允许在不改变设计关系的前提下微调具体数值。

## 6. 视觉系统

### 色彩

- Ink：`#0D1638`，标题与关键数字。
- Electric Blue：`#566FFF`。
- Lume Violet：`#7657F7`。
- Spectrum Magenta：`#DF5FD1`。
- Soft Coral：`#FF7D8D`。
- Cloud：`#F7F8FC`，页面与卡片底色。

大面积区域保持白色和低饱和冷灰。蓝、紫、粉、珊瑚色只集中在 Hero、主按钮、关键图标和 CTA。不得增加酸性荧光绿、纯黑大底或高对比霓虹描边。

### 字体

使用系统中文无衬线栈，以 `PingFang SC` 为首选，后备为 `Microsoft YaHei` 与通用 sans-serif。标题采用紧凑字距和较高字重；正文降低对比度并增加行距。

主要字号层级为 10、12、14、16、20、32 和 56 px，并在手机端按视觉稿收缩。最终数值以截图叠加结果校准。

### 材质与深度

- 卡片使用白色或近白半透明底、1 px 低对比边框、柔和长阴影和中等圆角。
- Hero Dashboard 使用真实半透明背景、`backdrop-filter` 和内高光，底层 Banner 负责综合色彩。
- 阴影不得使用纯黑硬边；统一采用偏冷的蓝灰或紫灰阴影。
- 页面只保留两个强视觉焦点：Hero 毛玻璃方块和 CTA 光学球体。

### 品牌与图标

- Logo 重绘为光谱色球形/有机形标记，内部使用简洁的光源或连接意象，配合“问答光源 | AskLume”字标和中文副标。
- 功能图标采用统一 SVG 体系：约 2 px 视觉线宽、圆角端点、蓝紫或粉珊瑚渐变、半透明浅色底座。
- 客户品牌标识采用低对比度单色近似图形和文字组合；不冒充官方商标精确文件。
- CTA 球体使用原创 SVG/CSS 光学渐变和柔和反射，不引入风格不一致的图库素材。

## 7. 动效

动效只发生在三个时刻：

1. 首屏入场（约 0–900 ms）：标题、说明和按钮依次淡入上移；Dashboard 稍晚出现；Banner 只做极轻微的光感呼吸。
2. 滚动进入：每个区块只触发一次，以 12–18 px 位移和透明度进入；Pillars 按阅读顺序轻微错峰。
3. 操作反馈（约 120–220 ms）：按钮、卡片和菜单提供轻微抬升、描边或颜色变化；手机菜单使用柔和遮罩和纵向展开。

不得让所有卡片持续漂浮，不使用鼠标跟随光斑，不使用大幅视差。`prefers-reduced-motion` 开启时关闭位移与呼吸动画，只保留即时显隐和颜色反馈。

## 8. 组件与数据边界

建议组件边界：

- `HomePage`
- `Header`
- `MobileMenu`
- `Hero`
- `GlassDashboard`
- `TrustStrip`
- `BenefitsSection`
- `PillarsSection`
- `CapabilitiesSection`
- `DiagnosticCTA`
- `MobileDashboard`
- `Footer`

卡片文案、数据、导航和品牌列表放在独立的类型化内容配置中，组件只负责呈现。页面没有远程数据流和表单提交；所有链接在本次范围内指向页面锚点或使用明确的占位目的地。

## 9. 失败与降级

- Banner 加载前保留相同宽高比和低饱和 CSS 渐变底色，避免布局跳动。
- Banner 加载失败时仍显示文字、按钮和 Dashboard，且渐变底色提供可接受的视觉兜底。
- `backdrop-filter` 不可用时使用更高不透明度的白色背景和等效阴影。
- JavaScript 不可用时页面内容保持可读，只有菜单开合和入场动画不可用。
- 图片具有明确尺寸；非首屏装饰资源延迟加载。

## 10. 可访问性

- 使用语义化标题层级、导航、按钮和链接。
- 所有交互控件提供可见键盘焦点。
- 手机菜单打开后锁定背景滚动，焦点进入菜单；关闭后焦点回到菜单按钮。
- 装饰 SVG 和光效从辅助技术中隐藏；有意义图形提供可理解标签。
- 正文、按钮文字和关键数字达到可读对比度。

## 11. 验收标准

### 视觉

- 在 1024 px 宽度与桌面稿逐屏截图叠加，校准区块高度、基线、间距、圆角、阴影、渐变和 Banner 定位。
- 在 390 px 宽度与手机稿逐段比对，确认卡片顺序、Dashboard 后置和菜单状态。
- 1440 px 和 360 px 下无失衡留白、文字溢出或横向滚动。

### 行为

- 桌面锚点导航、手机菜单开合、按钮状态和减少动效设置工作正常。
- 交互控件可由键盘访问，手机菜单焦点管理正确。

### 工程

- 类型检查、单元测试和生产构建通过。
- Playwright 覆盖 1440、1024、390、360 四种视口的关键截图。
- 页面不存在控制台错误、明显布局偏移或未设置尺寸的关键图片。

## 12. 不在范围内

- 后端接口、用户认证、搜索服务、国际化内容系统。
- 预约演示或诊断表单的真实提交。
- 产品与服务、解决方案、资源中心、关于我们等二级页面。
- CMS、数据分析、部署和域名配置。
- Three.js、复杂 WebGL 场景或视频生成。
